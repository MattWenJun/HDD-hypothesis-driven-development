# HDD — 假设驱动开发（Hypothesis-Driven Development）

[English](README.md) | **中文**

**一个让你的 AI agent 不再"信心十足地在错误前提上埋头干活"的 Skill。**

HDD 是一个 Agent Skill：一套用于诊断、debug、优化、选型、架构/配置变更的方法论——
适用于任何"结果不确定、需要*验证*而不能靠假设"的任务。

它的核心纪律很简单，但对人和 LLM 来说都反直觉：

> **一个假设，无论多笃定，在被可观测的证据确认之前，都只是假设。
> 光靠推理，不构成证据。**

---

## 为什么需要它

一个有能力的 agent，最贵的失败模式不是"答错"——而是**在一个错误假设之上空转很久，
直到交付那一刻才暴露**。HDD 把那个便宜的问题（"这个前提到底成不成立？"）
前置到昂贵的工作开始之前。

它还修复了最容易被忽略的那个假设:**agent 假定了自己的能力边界，却没去核实。**
所以整个流程从 *资源映射* 开始——在提出任何技术假设之前，先盘点你实际拥有的
工具、本地知识和外部入口。

## 流程

```
Step 0  →  HT  →  PT  →  AT Design  →  DEV  →  AT Run  →  E2E
```

- **Step 0 — 资源映射** —— 我有哪些资源可以解决这个问题？在认定"只能用笨办法绕过去"之前，
  先质疑每一个假定的限制是否真实存在。
- **HT — 假设验证** —— 赋先验、攻击自己的判断依据、达到真实的证据等级
  （V1 现场复现 / V2 证据链闭合）。纯推理是 V5——**零**证据权重。
- **PT — 方案验证** —— 用具体的测试用例验证方案可行。
- **AT Design — 验收用例编写** —— 在写代码*之前*先定义"做完长什么样"。
- **DEV — 开发** —— 基于方案 + 验收用例执行。
- **AT Run — 验收测试执行** —— 跑 AT Design 里定义的用例。
- **E2E — 端到端验收** —— 由用户亲自验收。

并带有明确的回退路径：方案失败回到方案；方案失败的根因在假设，则一路回退到 HT。

## 证据等级

| 等级 | 名称 | 贝叶斯更新力 |
|------|------|-------------|
| V1 | 现场复现 | 极高 |
| V2 | 证据链闭合 | 高 |
| V3 | 证据链部分闭合 | 中 |
| V4 | 类比证据 | 低 |
| V5 | 纯推理 | **零** |

对于事后诊断，**必须达到 V2 或 V1** 才能进入修复。

## 安装

HDD 与模型、harness 无关。把它放进你的 agent 加载 skill 的目录即可：

```bash
git clone https://github.com/MattWenJun/HDD-hypothesis-driven-development.git
# 然后把 SKILL.md 放进你 agent 的 skills 目录，例如：
#   ~/.your-agent/skills/hdd/SKILL.md
```

这个 skill 会在诊断 / debug / 优化 / 选型 / 架构变更类任务时激活，
或者当你手动说"用 HDD" / "先验证假设"时触发。它**刻意不**在
简单、确定的编辑上激活（改个标题、加个 import）。

> `SKILL.md` 里的工具名（读写文件、记忆检索、联网搜索、跑命令）是能力描述——
> 按你 agent 环境实际提供的工具替换即可。
